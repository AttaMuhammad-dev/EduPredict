# EduPredict release notes — 24 October 2026

## Application workflows

- A public read-only `/showcase` page and CSV download use six fixed synthetic fixtures without any database reads. The homepage links to this demonstration; actual staff routes remain protected. Two tests verify database independence and fixture-only download contents.

- Public registration always creates a student. Staff roles must be provisioned deliberately by an existing administrator.
- Every authenticated request checks the current account's active state and role. Password changes invalidate earlier sessions; API callers receive an authorization error rather than a successful HTML redirect.
- Analysts can upload normalized CSV data, view charts and train a demonstration model. Uploaded datasets belong to their creator; an administrator can review all records.
- Reports and report downloads use the same ownership scope. Teacher risk/anomaly reports include only their assigned cohort. Missing predictions are shown as unavailable rather than fabricated grades or percentages.
- Students can submit only tasks assigned to their cohort. Only the assigned teacher or an administrator can grade work or download its attachment. Grades must be finite and within the assignment's mark total.

## Durable serverless data

New dataset CSV content, generated report CSV content and submission attachment bytes are stored in the dedicated MongoDB demo database. Download routes enforce authorization before returning bytes. Temporary filesystem storage remains only for legacy compatibility and transient processing; it is not the authoritative location for new uploads/reports.

CSV uploads are bounded to 2 MB, 10,000 rows and 100 columns after normalization, and 20 datasets per account. Model training needs at least ten usable rows and permits at most twenty features. Student attachments are bounded to 2 MB and a limited set of document/image extensions. Requests are capped at 4 MB. These limits keep demonstration workloads suitable for free serverless hosting; this is not a malware-scanning or large-data platform.

## Input and access protection

Mutation requests with an unrelated Origin are rejected. JSON request bodies must be objects; account fields are validated before database use. Private/API responses are not cached. Internal server failures produce generic API errors. CSV report cells with spreadsheet formula prefixes are escaped.

## Deployment

Use Python 3.12 and the pinned requirements. Keep `MONGO_URI` and a random `SECRET_KEY` private. The portfolio deployment uses `DB_NAME=edupredict_demo`, HTTPS cookies and `EMAIL_ENABLED=false`. Changing a shared Atlas user's password requires replacing every affected private URI and redeploying each service. Never commit `.env.local` generated by hosting tools.

## Verification and remaining operating responsibilities

`python -m unittest discover -s tests -v` passes 24 isolated tests, including durable data after local-file loss, cross-account/cohort access denial and grade limits. The 24 October public deployment also passed eight synthetic student/account access checks. Real institutional data, email delivery, cloud-provider availability and the predictive validity of the synthetic models are outside that evidence. Continue maintaining dependencies, quotas and database backups; no free hosted application can promise indefinite uptime without maintenance.
